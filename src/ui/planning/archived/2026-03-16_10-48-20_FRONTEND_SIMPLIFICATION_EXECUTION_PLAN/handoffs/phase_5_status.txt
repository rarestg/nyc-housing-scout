Helper pattern used
-------------------
- Each route now owns a small route-local action builder:
- `PostsRoute.jsx`: `createPostsQueryActions(setQueryState)` with `updateFilters`, `openDetail`, `setPage`, and `setPageSize`
- `ReviewRoute.jsx`: `createReviewQueryActions(setQueryState)` with the same shape but review-specific selection clearing
- `DebugRoute.jsx`: `createDebugQueryActions({ navigate, searchParams, setQueryState })` keeps route-param selection local while still centralizing filter/page updates
- `ListingsRoute.jsx`: `createListingsQueryActions(setQueryState)` adds `clearFilters`, `syncSelectedListing`, and `clampPage` because Listings has the richer default-selection and page-bounds behavior
- The shared rule stayed local to each route: filter changes reset `page` when appropriate, Posts/Review/Listings clear query-state selection when appropriate, and Debug intentionally does not because its selection is the route param

Handoff summary
---------------
- Query-state boilerplate is materially smaller across all four routes because filter changes now flow through one small local helper per route instead of repeated inline `setQueryState({ page: 1, selectionId: '', ... })` patches.
- Listings keeps its intentionally richer route-local behavior: the helper also owns clear-all defaults, first-row default selection, and page clamping, while the route still keeps local chip/url builder logic rather than pushing more into shared code.
- Posts and Review intentionally keep separate helper builders even though their shapes are similar; the selection keys and route semantics differ enough that a new shared abstraction would have been worse than the remaining repetition.
- Debug intentionally keeps its route-param navigation and legacy `runId` stripping logic local; only filter/page updates were centralized there.
- Phase-specific validation passed: `npm test` and `npm run build:dashboard`.
- Route-behavior verification came from the passed dashboard query-state tests, the new route-local helper call paths, and a live Listings filter-bar snapshot against `inspect:ui`. Follow-up `agent-browser` URL assertions hung in this environment, so full interactive confirmation of post-change URLs was limited by the tool rather than a confirmed app regression.
