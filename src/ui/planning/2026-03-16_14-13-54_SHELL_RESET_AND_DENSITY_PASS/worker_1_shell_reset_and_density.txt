Mission
-------
Reset the dashboard shell and visual density so the listings workspace gets more width, the shell becomes easier to understand, and the detail pane/table become calmer and more legible.

Behavior guardrail
------------------
Preserve the current shell/query-state behavior while doing this visual reset:

- keep `detail=open|closed` behavior intact
- keep current row-selection and deep-link behavior intact
- keep off-page warning states intact
- if the top-nav or detail-header reset appears to require changing those semantics, stop and document the conflict instead of widening scope

Do not own
----------
- backend/storage/query logic

- data-quality/enrichment work

Required changes
----------------
1. Navigation
- replace the fixed left rail with a thin top nav
- use full text labels
- remove `HS`, `LS`, `PS`, `RV`, `DB`
- at narrower widths, keep the nav compact and legible without awkward multi-row sprawl or horizontal overflow

2. Shell flattening
- reduce the "cards inside cards" feeling
- simplify and reduce border radii globally
- prefer a small radius-token system over repeated hard-coded values
- use at most three radius tokens across the main dashboard surface system
- reassess shell max width, outer padding, and detail width so the table gets more room

3. Filters and controls
- keep the compact filter bar model
- fix the layout bug where `More filters` and `Clear filters` stack vertically and waste height
- make the controls feel denser and more intentional

4. Detail pane
- pin the close affordance in the top-right corner
- reduce detail title size and weight
- keep source / author / posted time high in the hierarchy
- make metadata feel different from actions
- make actions visibly clickable without using oversized pill buttons that look too similar to metadata

5. Table typography
- quiet the table hierarchy
- reduce oversized/bold text
- keep Listings strongest
- de-emphasize source/time/location/rooms/supporting columns
- target table primary text around `13px / 600`
- target meta/supporting text around `11-12px`
- reserve the strongest emphasis for the Listings column and truly exceptional status states

6. Cross-route alignment
- Posts, Review, and Debug should inherit the shell reset cleanly
- Debug should remain clearly advanced/forensic, but visually aligned

Important style guidance
------------------------
- Do not merely square everything off.
- Do introduce a smaller, clearer radius system.
- Do keep that radius system to at most three tokens across the main dashboard surface system.
- Do not create a new decorative card language.
- Prefer cleaner and calmer over "more UI."
- If a simpler layout can remove code and visual noise at the same time, prefer that.

Constraints
-----------
- Do not hand-edit `src/ui/dashboard/dist/app.js`.
- Do not widen into backend or route-contract work.
- Do not reopen the simplification sprint's behavioral deletions unless you hit a proven regression.
- Do not turn this into a brand/design-system exploration.
- Do not change route-selection/query-state semantics unless you hit a proven regression and document it first.
