Dispatch Protocol
=================

How to dispatch a worker
------------------------
1. Give the worker only their worker file.
2. Tell them to follow the read order in `README.txt`.
3. Tell them to read all prior handoff files if their phase depends on earlier work.
4. Tell them to update only their assigned handoff file:
   - at start
   - at blocker
   - at finish

Rules for workers
-----------------
- Do not widen into another phase silently.
- Do not overwrite raw observation, payload, or listing rows.
- Do not build UI before the backend contract for that state exists.
- Do not let `Debug` become editorial.
- Prefer explicit storage helpers and direct tests over compatibility layers.

Rules for the dispatcher
------------------------
- Do not dispatch Worker 2 before Worker 1 is stable.
- Do not dispatch Worker 4 before Worker 3 is stable.
- Do not dispatch Worker 6 before Worker 5 is stable.
- If a phase discovers a contract problem that changes the next phase, update the coordination board before dispatching again.

What not to re-open
-------------------
- whether SQLite remains canonical
- whether collection should own enrichment
- whether the frontend should fake manual/resolved states first
- whether `Debug` should become the correction surface
